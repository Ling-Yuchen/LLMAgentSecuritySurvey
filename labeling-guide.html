Labeling guide

This guide defines the public annotation fields, their decision boundaries, and the compact labels shown in the literature browser. It brings together the survey’s annotation scheme, lifecycle definitions, and existing label conventions.

Each record describes one retained literature entry. Paper type and system setting have one assignment; technical fields allow multiple labels. Labels describe the contribution, setting, or evidence discussed in the source. For quantitative comparisons, use the source’s stated threat model, experiment, and metric denominator.

1. Field reference

Identify the paper’s main contribution first, then its agent setting and security concern. Assign technical labels to substantively treated mechanisms, settings, or evaluation resources. Preserve distinct concepts when a paper combines them.

2. Paper type and system setting

Attack
The main contribution develops or demonstrates a compromise mechanism or adversarial method.
Defense
The main contribution develops or assesses a protection mechanism.
Benchmark
The main contribution is a reusable task collection, dataset, testbed, or evaluation protocol.
Evaluation
The main contribution measures or diagnoses existing agents, risks, or controls, rather than introducing a benchmark as its central output.
Survey
The work primarily synthesizes existing literature, taxonomies, or research directions.
Report
A system card, deployment report, security advisory, or comparable technical report. The website groups Report, System Card, and Advisory under this label.

Mixed contributions. Use the paper’s central objective and principal output to distinguish Attack, Defense, Benchmark, and Evaluation. A benchmark paper can contain attacks and defenses without receiving multiple primary types. Venue and preprint status are separate bibliographic attributes. Report identifies the document’s role, not the strength of every claim within it.

Multi-agent = Yes when agent-to-agent communication, coordination, collaboration, interoperability, topology, or cross-agent influence is a central security concern. No indicates that this criterion is not met. A passing discussion of multi-agent risks can support a topic tag without making the entire paper multi-agent-focused.

Topic labels can overlap. A paper about poisoned retrieval memory can receive both Memory Safety and RAG Security. Additional source-specific topic phrases retain their literal research focus, such as Post-Training Local LLM Agents.

Agent type is open vocabulary. Tool-using, planning, memory-augmented, and RAG agents describe capabilities or architecture; web, GUI, computer-use, coding, and embodied agents describe interfaces or operational settings. Role labels such as email assistant or healthcare agent describe the intended service. Record multiple applicable characteristics. Coding Agent and Code Agent, or RAG Agent and Retrieval-Augmented Agent, express closely related descriptions rather than mutually exclusive classes.

Task scenario is open vocabulary. Use the application and task actually studied, such as Web Browsing, Computer Use, Software Engineering, Email Workflows, Finance Tools, Healthcare Assistance, Embodied Robotics, Plugin Ecosystem, Cloud Office Tools, Smart Home / IoT, Consumer App Automation, Personal Assistance, Critical Infrastructure, Cybersecurity Testing, or Multi-agent Collaboration. Preserve a short source-specific description when these general terms do not capture the task. A benchmark name alone does not establish every scenario it could support.

4. Lifecycle stages

Lifecycle labels identify which agent process is affected. Assign the processes substantively addressed in the work, including more than one stage when a mechanism crosses stages. Merely using an agent does not assign every stage.

Input
Inbound context and observations entering the agent.
Planning
Task decomposition, intermediate reasoning, or generation of candidate trajectories.
Decision
Commitment to one next action or delegation target.
Tool Execution
The privileged act performed through a tool or environment interface.
Memory
Transient or persistent state, including retention, updates, and later reuse.
Output
Externally visible responses, results, and side effects.
Monitoring
Observation and checking of agent behavior during operation.
Inter-agent Comms
Messages or information exchanged between agents.
Coordination
Organization of joint activity, roles, delegation, and cooperation across agents.

Boundary rule. Forming a plan, choosing an action, and executing that action are separate assignments. A message exchange supports Inter-agent Comms; its effect on joint work can additionally support Coordination. Monitoring describes checking behavior, while Coordination describes organizing it.

The survey’s system tuple uses I, P, D, T, M, O, and C to model information, action, state, and coordination channels. The labels above provide the finer process categories used in its corpus discussion. Auxiliary descriptions of initialization, post-hoc auditing, or multi-turn interaction are not added as independent website lifecycle stages or automatically reassigned to these nine labels.

5. Threat models and attack surfaces

Threat-model tags
Prompt Injection
Instructions intended to redirect agent behavior. This broad tag can coexist with a more specific injection tag.
Indirect Prompt Injection
Attacker instructions carried by lower-trust content encountered during a task.
Jailbreak Prompts
Requests or prompt manipulations targeting behavioral safety restrictions.
Unsafe User Instructions
Harmful, malicious, or underspecified instructions from the user-facing input.
Untrusted External Content
External material that can influence the agent without trusted instruction authority.
Malicious Tools / Plugins / Apps
Adversarial or compromised tool, plugin, or application components. Retain the component-specific tag.
Memory Poisoning
Adversarial contamination of state that can influence subsequent behavior.
Backdoor Triggers
Trigger-conditioned activation of attacker-chosen behavior.
Privilege Abuse
Misuse of authority, credentials, or available capabilities.
Data Exfiltration
Unauthorized disclosure or transfer of information.
Agent Misbehavior
Unsafe behavior arising from agent errors or failure processes.
Agent as Attacker
An agent acts as the offensive actor rather than only as the victim.
Coordination Failures
Security-relevant failures in interactions or joint agent activity.
Environmental Injection
Manipulation carried through observations, interfaces, notifications, or environmental content.

Threat tags summarize a concern or failure source. Preserve distinctions between attacker-controlled components and non-adversarial failures; a shared outcome such as leakage does not imply identical attacker access.

Surface definitions and assignment boundaries
User Prompts / System Prompts
User-supplied requests versus system instructions or templates. Preserve the instruction source and authority.
Web Content
Content encountered in browsing, including pages, DOM, links, and rendered web material.
Retrieved Content
Evidence returned by retrieval or search, including documents and knowledge-base material.
Tool Outputs
Results returned by an invoked tool or API.
Tool Inputs / Tool Metadata
Invocation arguments versus names, descriptions, schemas, or other tool-selection information.
Plugin / API Interfaces
Integration contracts and interfaces through which external components interact with the agent.
Files / Code
Local artifacts that may be read, executed, or modified.
Memory / Scratchpads
Agent-generated or retained state, including reusable working context.
Planning Loop / Action Selection / Action Generation
Reasoning, choice, or production of actions when that internal process is the manipulated asset.
Inter-agent Channels
Messages, shared communication structures, and routes between agents.
Execution Environment / Sandbox State
Runtime resources and state available to executed actions.
Auth / Permission Flows
Identity, authorization, confirmation, and permission handling.
Environment State / Mobile UI / Notifications
Physical, simulated, or graphical observations and interaction surfaces.
Agent Outputs / Model Responses
Generated content or responses exposed to manipulation or disclosure.

Detailed surface names remain open vocabulary. Retain the concrete asset or channel when it is more informative, for example an email subject, MCP registration metadata, or a skill script. A webpage returned by a browsing tool can involve both Web Content and Tool Outputs when both provenance and the return interface matter. Stage records when the risk acts; surface records where it enters or which asset it affects.

6. Attacks, defenses, benchmarks, and metrics

Attack methods

Use a short mechanism label or the source’s named method. Direct injection enters through the direct instruction interface; indirect injection enters through task-time external content. Tool poisoning changes tool metadata or behavior; memory poisoning changes retained state; data exfiltration sends information to an unauthorized recipient; goal hijacking changes the objective; role spoofing impersonates an authority; message tampering alters inter-agent communication. Backdoors, visual perturbations, tool denial of service, and cost amplification retain their distinct mechanism names.

Multiple mechanisms can apply to one paper. Preserve a specific method name such as GCG, MINJA, or CORBA when it identifies the evaluated technique. A paper’s title or primary type alone does not determine all of its attack labels.

Defense methods

Label the intervention. Filtering or sanitization checks content; instruction hierarchy or trust delimiters separates instruction authority; isolation or sandboxing separates execution contexts; access control and least privilege constrain capabilities; monitoring observes runtime behavior; intent or plan verification checks alignment before action; provenance and authentication verify origins; memory controls govern retained state; safety training changes model behavior; human confirmation introduces a human decision.

Retain named defenses when available and assign several labels for genuinely combined controls. A defense label identifies a mechanism addressed by the paper, including evaluated baselines and survey discussions. Its effectiveness and deployment assumptions come from the associated evidence. Attack optimization constraints and experimental setup choices are not recast as protection mechanisms.

Benchmarks and datasets

Preserve resource names such as AgentDojo, InjecAgent, ASB, OSWorld, or MIMIC-III. Use a short descriptive label for study-specific resources, such as Web tasks, MCP testbed, or Custom scenarios. These entries can be security benchmarks, capability benchmarks, datasets, or bespoke evaluation environments. Resource use or discussion records research activity; security capability depends on the actual attacker interface, state, interaction horizon, and outcome criteria tested.

Evaluation metrics

Preserve the measured quantity. ASR means attack success rate; Task success denotes task completion; Accuracy, Precision, Recall, F1, AUROC describe prediction or detection quality; Utility describes retained task performance; Refusal Rate describes refusal frequency; Latency, Cost, Token Usage describe resource use. ELR and WLS denote exact leakage rate and weighted leakage score. Keep source-specific metrics by name when their definition differs.

Generic Success Rate remains generic unless its target is specified. A label alone does not harmonize denominators, attackers, repeated attempts, judges, or operating conditions across studies. Qualitative criteria remain qualitative labels rather than invented numeric scores.

7. Multiple labels, missing values, and compact summaries

  1. Multiple labels. Technical arrays contain distinct applicable labels. For a full annotation table, count a paper at most once per label or label pair. Counts across overlapping labels need not sum to the corpus size.
  2. Missing values. Empty arrays display “Not specified”. They do not distinguish not applicable, not reported, and not assigned. Treat them as unspecified, not as an explicit negative observation. Legacy “Not-Specified” or availability-only topic messages likewise carry no topical assignment.
  3. Open vocabulary. Resource names, metrics, keywords, agent descriptions, scenarios, concrete surfaces, and named methods can extend beyond the recurring labels listed here. Keep a concise source-specific term instead of forcing an unrelated category.
  4. Compact publication. Benchmark, metric, attack, and defense summaries retain up to two distinct representative labels, with at most six English words per field. Descriptive sentences are condensed by meaning, specific names are retained where useful, and synonymous summaries are merged. The current release takes the first two distinct summaries in the retained annotation order; that order is not an effectiveness ranking.
  5. Lifecycle display. Retain all recorded labels that match the nine lifecycle categories and display them in the order listed in Section 4. This preserves the distinction between planning, decision, execution, state, and coordination.
  6. Evidence and counts. Use all document types for corpus-composition questions. Attribute empirical outcomes to the relevant primary studies or report evidence. Separate Survey and Report when a count is intended to characterize primary research. State the included types, missing-value treatment, and denominator for each analysis.

The browser’s two-label summaries support exploration. Full multi-label frequency or co-occurrence calculations use the corresponding analysis annotations, because summarization can omit labels or combine synonymous descriptions.

Boundary review. Resolve competing assignments against the source’s stated contribution, system setting, and described mechanism, using the same boundary across papers. Leave an unsupported assignment unspecified. For agreement analysis, a single-label field is categorical and each multi-label category is a separate binary decision. The survey reports agreement before harmonization; the browser summaries are a subsequent presentation layer.

8. Applying the boundaries

A poisoned webpage redirects a tool call
Web Content identifies the entry surface; Indirect injection identifies the manipulation. Input, Decision, and Tool Execution apply when the work substantively follows those processes. Add Planning only when the mechanism or analysis addresses planning.
A malicious memory affects a later task
Memory / Scratchpads identifies the asset and Memory the lifecycle process. Memory poisoning names the attack. Label the later planning or decision effect when it is examined.
A paper introduces a benchmark and tests defenses
Use Benchmark as the primary type when the reusable evaluation resource is the main contribution. Record the studied defenses separately.
A survey discusses agent communication
Multi-agent Security can be a research topic. Set Multi-agent to Yes only if cross-agent security is central to the work’s focus.

Basis. The survey’s Literature Annotation and Analysis subsection, LLM Agent Security Scope and Modeling section, and Annotation Encoding, Boundary Cases, and Reliability appendix supply the scheme and distinctions. This guide documents the public field meanings and current summary conventions.
