2. Paper Type And System Setting

Attack
The main contribution develops or demonstrates a compromise mechanism or adversarial method.
Defense
The main contribution develops or assesses a protection mechanism.
Benchmark
The main contribution is a reusable task collection, dataset, testbed, or evaluation protocol.
Evaluation
Measures existing agents, risks, or controls; a new benchmark is not the main output.
Survey
The work primarily synthesizes existing literature, taxonomies, or research directions.
Report
Technical reports, including system cards and security advisories.

Mixed Contributions. Choose the primary type by the central objective and output. Record additional attacks, defenses, and resources in their own fields. Publication venue is a separate attribute.

Multi-Agent = Yes when communication, coordination, collaboration, interoperability, topology, or cross-agent influence is central to the security question. Otherwise use No. A topic mention alone does not establish a multi-agent focus.

Agent Type. Record architecture, interface, modality, or role, such as tool-using, memory-augmented, coding, embodied, or email agents. Multiple descriptions may apply; synonymous names express the same concept.

Task Scenario. Name the application actually studied, such as web browsing, software engineering, healthcare, finance, robotics, or multi-agent collaboration. Use a short specific description when needed.

4. Lifecycle Stages

Lifecycle labels identify the affected process. Assign each stage substantively examined, including multiple stages for cross-stage mechanisms.

Input
Inbound context and observations entering the agent.
Planning
Task decomposition, intermediate reasoning, or generation of candidate trajectories.
Decision
Commitment to one next action or delegation target.
Tool Execution
The privileged act performed through a tool or environment interface.
Memory
Transient or persistent state, including retention, updates, and later reuse.
Output
Externally visible responses, results, and side effects.
Monitoring
Observation and checking of agent behavior during operation.
Inter-Agent Comms
Messages or information exchanged between agents.
Coordination
Organization of joint activity, roles, delegation, and cooperation across agents.

Stage Boundaries. Planning forms a trajectory, Decision commits to an action, and Tool Execution performs it. Inter-agent Comms exchanges information; Coordination organizes joint work; Monitoring checks behavior.

These nine labels refine the survey’s I, P, D, T, M, O, C system model. Initialization, post-hoc auditing, and multi-turn interaction are not separate website stages.

5. Threat Models And Attack Surfaces

Threat-Model Tags
Prompt Injection
Instructions intended to redirect agent behavior. This broad tag can coexist with a more specific injection tag.
Indirect Prompt Injection
Attacker instructions carried by lower-trust content encountered during a task.
Jailbreak Prompts
Requests or prompt manipulations targeting behavioral safety restrictions.
Unsafe User Instructions
Harmful, malicious, or underspecified instructions from the user-facing input.
Untrusted External Content
External material that can influence the agent without trusted instruction authority.
Malicious Tools / Plugins / Apps
Adversarial or compromised tool, plugin, or application components. Retain the component-specific tag.
Memory Poisoning
Adversarial contamination of state that can influence subsequent behavior.
Backdoor Triggers
Trigger-conditioned activation of attacker-chosen behavior.
Privilege Abuse
Misuse of authority, credentials, or available capabilities.
Data Exfiltration
Unauthorized disclosure or transfer of information.
Agent Misbehavior
Unsafe behavior arising from agent errors or failure processes.
Agent As Attacker
An agent acts as the offensive actor rather than only as the victim.
Coordination Failures
Security-relevant failures in interactions or joint agent activity.
Environmental Injection
Manipulation carried through observations, interfaces, notifications, or environmental content.

Distinguish attacker-controlled components from agent failures. A shared outcome, such as leakage, can arise under different access assumptions.

Surface Definitions And Assignment Boundaries
User Prompts / System Prompts
User-supplied requests versus system instructions or templates. Preserve the instruction source and authority.
Web Content
Content encountered in browsing, including pages, DOM, links, and rendered web material.
Retrieved Content
Evidence returned by retrieval or search, including documents and knowledge-base material.
Tool Outputs
Results returned by an invoked tool or API.
Tool Inputs / Tool Metadata
Invocation arguments versus names, descriptions, schemas, or other tool-selection information.
Plugin / API Interfaces
Integration contracts and interfaces through which external components interact with the agent.
Files / Code
Local artifacts that may be read, executed, or modified.
Memory / Scratchpads
Agent-generated or retained state, including reusable working context.
Planning Loop / Action Selection / Action Generation
Reasoning, choice, or production of actions when that internal process is the manipulated asset.
Inter-Agent Channels
Messages, shared communication structures, and routes between agents.
Execution Environment / Sandbox State
Runtime resources and state available to executed actions.
Auth / Permission Flows
Identity, authorization, confirmation, and permission handling.
Environment State / Mobile UI / Notifications
Physical, simulated, or graphical observations and interaction surfaces.
Agent Outputs / Model Responses
Generated content or responses exposed to manipulation or disclosure.

Keep concrete surface names when useful, such as an email subject or skill script. A browsed page may involve both Web Content and Tool Outputs. Surface identifies the entry channel or asset; lifecycle identifies the affected process.

6. Methods And Evaluation

Attack Methods

Name the manipulation or retain a named technique such as GCG, MINJA, or CORBA. Direct injection uses the instruction interface; indirect injection uses external task content. Tool poisoning alters tools, memory poisoning alters state, exfiltration discloses data, and goal hijacking redirects the objective.

Assign multiple attack labels when distinct mechanisms are studied.

Defense Methods

Name the intervention: content filtering, instruction separation, isolation, access control, monitoring, intent verification, provenance, memory protection, safety training, or human confirmation. Retain named defenses and label combined controls separately.

Labels include proposed mechanisms, evaluated baselines, and survey discussions. Effectiveness comes from the associated evidence; attack optimization constraints are not defenses.

Benchmarks And Datasets

Keep names such as AgentDojo, InjecAgent, ASB, OSWorld, and MIMIC-III. Summarize bespoke resources as Web tasks, MCP testbed, or Custom scenarios. Distinguish security benchmarks, capability benchmarks, datasets, and testbeds. Resource use alone does not establish tested security coverage.

Evaluation Metrics

ASR is attack success rate; Task Success is task completion. Accuracy, Precision, Recall, F1, and AUROC measure prediction quality. Utility measures retained performance; Refusal Rate measures refusals; Latency, Cost, and Token Usage measure resources. ELR is exact leakage rate and WLS is weighted leakage score.

Keep source-specific metric names and denominators. Leave generic Success Rate generic when its target is unspecified, and retain qualitative criteria as qualitative labels.

7. Encoding And Summaries

  1. Multiple Labels. Count each paper once per label or label pair. Overlapping label counts need not sum to the corpus size.
  2. Missing Values. Empty arrays display “Not specified” and combine not applicable, not reported, and not assigned. Treat them as unspecified rather than negative observations. Legacy availability-only messages carry no topic assignment.
  3. Open Vocabulary. Retain concise source-specific names for resources, metrics, keywords, agents, scenarios, surfaces, and methods.
  4. Compact Summaries. Benchmarks, metrics, attacks, and defenses each retain the first two distinct summaries in annotation order, up to six English words. Merge synonymous descriptions and preserve useful names. Order does not rank effectiveness.
  5. Lifecycle Display. Retain all recorded labels matching the nine categories, in the order shown above.
  6. Evidence And Counts. Use all types for corpus composition; distinguish Survey and Report when counting primary research. Specify included types, missing-value handling, and denominators.

Compact summaries support browsing. Full frequency and co-occurrence calculations use the corresponding analysis annotations.

Boundary Review. Resolve ambiguities against the source’s contribution, setting, and mechanism. Leave unsupported assignments unspecified. Agreement uses categorical single-label decisions and binary multi-label decisions before harmonization.

8. Boundary Examples

A Poisoned Webpage Redirects A Tool Call
Surface: Web Content. Attack: Indirect injection. Assign the input, planning, decision, or execution stages actually examined.
A Malicious Memory Affects A Later Task
Surface: Memory / Scratchpads. Stage: Memory. Attack: Memory poisoning. Add later stages when their effects are examined.
A Paper Introduces A Benchmark And Tests Defenses
Primary type: Benchmark when the reusable resource is central. Record defenses separately.
A Survey Discusses Agent Communication
Multi-agent Security may be a topic; Multi-Agent is Yes only when cross-agent security is central.

Basis. The survey’s annotation methodology, lifecycle definitions, and annotation-reliability appendix.
